## Executive summary

The project now has the foundations of a real interactive chat REPL without
changing its public C API or its script-friendly one-shot behavior. Running
bare `oi` on a terminal enters the REPL; passing a prompt or redirecting input
continues to use one-shot mode (`src/cli.c:501-525`,
`docs/REPL_PLAN.md:7-14`).

The completed work includes:

- a private, owned conversation-message representation;
- a versioned append-only CLI history schema and strict JSON codec;
- protocol-valid history replay and interrupted-turn repair;
- an event-driven, reusable conversation engine shared by one-shot and
  interactive modes;
- UTF-8-aware multiline editing, bounded input history, raw terminal mode,
  input decoding, prompt state, ANSI rendering, and PTY-tested prompt I/O;
- automatic per-user session paths and lazy creation on the first submitted
  model message;
- a typed slash-command registry, live filterable command selector, literal
  `//` escape, and safe idle command dispatch;
- working `/help`, `/exit`, `/status`, and process-scoped `/permissions`
  commands.

This is substantial infrastructure, not the completed REPL milestone. Session
metadata and lifecycle management, durable `/model` and `/cwd`, compaction,
stream sanitization and Markdown, resize-safe concurrent redraw, active-turn
cancellation, queued input, REPL-native permission selection, and complete
documentation remain open. Those gaps are tracked in GitHub issues
[#20](https://github.com/zo-ll/oi.c/issues/20) through
[#30](https://github.com/zo-ll/oi.c/issues/30).

The feature work from `766da52` through `6423a48` changes 68 files with 11,223
insertions and 647 deletions. It was intentionally delivered as small,
single-concern commits; see [Commit map](#commit-map).

## Product contract and design decisions

The agreed product contract is recorded in `docs/REPL_PLAN.md:16-37`.
Important decisions are:

- Bare interactive startup always begins a brand-new session
  (`docs/REPL_PLAN.md:7-10`).
- New interactive sessions are not written to disk until the first model
  message is submitted (`docs/REPL_PLAN.md:95-98`).
- Durable history is the source of truth. Metadata and any future indexes are
  rebuildable derivatives (`docs/REPL_PLAN.md:82-101`).
- `/model` and `/cwd` are durable session settings. Permission policy and
  other runtime settings are process-scoped (`docs/REPL_PLAN.md:95-98`).
- One user item may eventually be queued while a turn is active. It should run
  immediately after the current tool reaches a safe boundary, and no newly
  requested tool should jump ahead of it (`docs/REPL_PLAN.md:31-33`,
  `docs/REPL_PLAN.md:54-56`).
- `//text` sends a literal user message beginning with `/`
  (`docs/REPL_PLAN.md:54-56`).
- Manual compaction should retain a durable summary tied to an exact source
  record range. A future vector index may be rebuilt from the durable log, but
  semantic retrieval is outside this milestone (`docs/REPL_PLAN.md:100-103`).
- All REPL functionality stays private to the CLI. The public library remains
  concerned with generic reactor, model, tool, session, and persistence
  primitives (`docs/REPL_PLAN.md:12-14`).

The supporting architecture decisions are:

- `docs/adr/0001-versioned-conversation-records.md`: versioned conversation
  records;
- `docs/adr/0002-manual-context-checkpoints.md`: manual context checkpoints;
- `docs/adr/0003-per-user-session-storage.md`: per-user session storage.

## Current architecture

### Public library versus private CLI

The public library sources remain the reactor, networking/model, tool,
session-log, arena/JSON, and configuration layers (`Makefile:29-31`). The
entire REPL is composed from private `src/cli_*` modules and linked only into
the CLI (`Makefile:60-61`, `Makefile:109-110`). No REPL symbol was added to the
public ABI.

The intended separation is documented at `docs/REPL_PLAN.md:58-80`:
conversation state does not belong to terminal code, terminal code does not
drive requests or interpret durable records, and only terminal presentation
modules should emit terminal control sequences.

### CLI composition and mode selection

`src/cli.c` remains the composition root. It:

- parses configuration and selects interactive versus one-shot operation;
- creates the reactor, model client, arena, and tool registry;
- restores an explicitly named legacy session;
- prepares automatic interactive sessions lazily;
- translates conversation events into durable history records; and
- dispatches into the one-shot loop or REPL.

Bare execution becomes interactive only when both standard input and standard
output are terminals. Redirected input and explicit prompt arguments remain
one-shot (`src/cli.c:501-525`).

An explicit `--session ID` still uses the pre-REPL flat
`SESSION_DIR/ID.oilog` layout (`src/cli.c:558-572`). It loads and validates
existing records, appends a schema transition when necessary, repairs an
interrupted final turn, reconstructs active model context, and attaches live
persistence (`src/cli.c:616-675`).

Automatic interactive sessions use a separate lazy-preparation path. The
first real model message creates the private location, opens `history.oilog`,
loads/initializes the typed store, appends a transition, wires event
persistence, and returns the session arena (`src/cli.c:220-268`). Commands
handled before that first message therefore do not create an empty session.

### Owned messages

`cli_message` owns copies of message content, tool-call IDs/names/arguments,
and tool result data rather than retaining transient parser or callback
buffers. This gives the conversation, replay, and persistence layers explicit
lifetime boundaries.

### Durable history

`cli_history` defines schema version 1 and bounded field sizes
(`src/cli_history.h:10-12`). Its record kinds are:

- schema transition;
- completed message;
- tool-started audit marker;
- partial assistant response;
- queued input;
- queue resolution; and
- context checkpoint (`src/cli_history.h:14-23`).

The last three runtime features are deliberately represented in the schema
before their controllers are implemented. Setters exist for queued input,
queue resolution, and checkpoints (`src/cli_history.h:104-132`), and replay
understands all three (`src/cli_history_replay.c:324-378`), but the active
REPL does not yet produce or act on them.

`cli_history_codec` encodes one stable JSON envelope per session-log record and
strictly rejects malformed or unsupported input. IDs are encoded as decimal
strings to preserve the complete `uint64_t` range. A real user-message record
shape is asserted by `test/test_cli_history_codec.c:8-33`:

```json
{"version":1,"record_id":"18446744073709551615","turn_id":"42","type":"message","role":"user","content":"hello","source":"normal"}
```

Assistant tool calls are owned nested values
(`test/test_cli_history_codec.c:35-63`). Raw tool bytes are preserved as
base64 alongside a typed outcome (`test/test_cli_history_codec.c:65-87`).
Queue audit records and checkpoint source ranges also have stable encoded IDs
(`test/test_cli_history_codec.c:120-147`).

`cli_history_store` bridges these typed records to the existing append-only
`sesslog` implementation. `cli_history_replay` enforces turn and tool protocol
ordering while rebuilding active context. `cli_history_repair` emits explicit
repair records when the last durable turn was interrupted, so recovery does
not silently mutate history.

Live event persistence is centralized in `src/cli.c:290-343`: completed
messages, tool-start markers, and partial assistant output are mapped from
semantic conversation events to monotonic record and turn IDs.

### Conversation engine

`cli_conversation` owns active model context and model/tool sequencing. Its
public-private boundary is an event API rather than direct terminal output.
The event union covers assistant deltas, complete messages, tool start/output,
partial output, response completion, model errors, and turn completion
(`src/cli_conversation.h:22-63`). The callback is synchronous and borrowed
event data is valid only during the call (`src/cli_conversation.h:66-82`).

The object can be created once, started for repeated user turns, queried for
busy state, and cancelled (`src/cli_conversation.h:84-102`). One-shot mode and
the REPL both consume it through shared presentation code.

The REPL currently starts a turn and then blocks in `oi_reactor_step` until
the presentation layer reports completion (`src/cli_repl.c:154-166`). It
cancels only as cleanup after an error and then exits the REPL
(`src/cli_repl.c:167-171`). This is why concurrent editing, queued input,
interactive cancellation, and recoverable errors remain future work.

### Presentation

`cli_present` is the shared semantic event consumer for one-shot and
interactive modes. It currently:

- writes assistant delta bytes directly to output;
- prints a tool-start marker;
- prints model errors and the final newline; and
- records completion status.

The direct byte write is at `src/cli_present.c:129-137`. Tool-output events
are currently ignored at `src/cli_present.c:148-151`. Consequently this layer
is not yet a control-byte sanitizer, Markdown renderer, or live tool-output
view.

### Editor and terminal stack

The input stack is split into small layers:

- `cli_utf8`: strict UTF-8 boundaries and code-point movement;
- `cli_editor`: owned multiline text/cursor state;
- `cli_input_history`: bounded submitted-prompt history;
- `cli_terminal`: enter/restore POSIX terminal mode;
- `cli_input`: pure byte-sequence decoding;
- `cli_prompt_state`: composes editor, history, paste, and command-menu state;
- `cli_render`: ANSI prompt/menu drawing;
- `cli_prompt`: file-descriptor I/O and terminal cleanup.

`cli_prompt` draws once, reads decoded input, updates pure prompt state, and
redraws the editor or command selector (`src/cli_prompt.c:51-107`).
`cli_render` exposes separate ordinary-prompt and command-menu draws
(`src/cli_render.c:274-279`). This keeps escape-sequence output out of the
conversation controller.

The editor supports UTF-8 code-point movement, multiline input, `Ctrl+J`
newline, bracketed paste, history derived from earlier user messages, and a
filterable slash selector. It intentionally does not yet implement full
grapheme-cluster editing (`docs/REPL_PLAN.md:26-28`,
`docs/REPL_PLAN.md:100-103`).

### Slash commands

`cli_commands` is the single typed registry used by parsing, filtering,
rendering, and help. The currently registered commands are `/help`, `/exit`,
`/session`, `/model`, `/permissions`, `/status`, `/compact`, and `/cwd`
(`src/cli_commands.c:9-23`).

`cli_repl` parses every submitted prompt before creating a conversation:

- unknown slash commands produce an error and return to the prompt;
- known commands dispatch without being sent to the model;
- `//` removes one slash and sends the remainder as a normal message; and
- ordinary messages lazily create the conversation/session
  (`src/cli_repl.c:83-152`).

Implemented command behavior:

- `/help`: registry-driven command and key help
  (`src/cli_command_dispatch.c:19-40`);
- `/exit`: clean idle exit (`src/cli_command_dispatch.c:123-130`);
- `/status`: current session ID, model, permission policy, and process CWD
  (`src/cli_command_dispatch.c:43-60`);
- `/permissions [ask|allow|deny]`: inspect or mutate the process-scoped policy
  (`src/cli_command_dispatch.c:70-97`).

`/session`, `/model`, `/compact`, and `/cwd` are registered for discovery but
currently report that they are not implemented
(`src/cli_command_dispatch.c:99-104`,
`src/cli_command_dispatch.c:139-143`).

## Runtime flows

### New interactive session

1. Bare `oi` with terminal stdin/stdout selects REPL mode
   (`src/cli.c:501-525`).
2. The REPL initializes history, presentation, and reusable conversation
   configuration (`src/cli_repl.c:37-75`).
3. The prompt enters raw terminal editing and presents command completion.
4. Safe slash commands execute without creating a durable session
   (`src/cli_repl.c:90-127`).
5. On the first normal message, the lazy preparation callback creates a
   timestamped private session directory and `history.oilog`
   (`src/cli_repl.c:132-147`, `src/cli.c:220-268`).
6. A reusable conversation object runs the turn on the existing reactor.
7. Presentation streams the assistant response while the persistence callback
   appends typed audit/context records.
8. The completed conversation remains alive for the next prompt
   (`src/cli_repl.c:77-175`).

### Automatic session paths

On Linux, the root is `$XDG_STATE_HOME/oi/sessions`, falling back to
`$HOME/.local/state/oi/sessions` (`src/cli_sessions.c:128-140`). The directory
tree is created with private permissions (`src/cli_sessions.c:46-85`).
Session IDs are timestamp-derived safe filename stems, and the returned paths
identify a per-session directory plus `history.oilog`
(`src/cli_sessions.c:143-219`).

The design calls for the macOS application-support location
(`docs/REPL_PLAN.md:90-93`), but issue #21 should verify and complete all
platform lifecycle behavior before this is treated as final.

### Restoring named one-shot history

1. `--session ID` resolves the existing flat `.oilog` path
   (`src/cli.c:558-572`).
2. The store loads typed and legacy records.
3. A schema transition is appended if required.
4. Interrupted terminal state is repaired durably.
5. Replay reconstructs protocol-valid active messages.
6. The one-shot conversation runs with live event persistence attached
   (`src/cli.c:616-675`).

This legacy explicit-session path and the new automatic directory layout have
not yet been unified. Import and selection are part of issue #21.

## Open work and known limitations

### #20 — session metadata, `/model`, and `/cwd`

Issue: https://github.com/zo-ll/oi.c/issues/20

There is no `metadata.json` implementation yet even though it is part of the
storage contract (`docs/REPL_PLAN.md:82-98`). `/model` and `/cwd` are only
registry entries and deferred dispatch cases
(`src/cli_command_dispatch.c:139-143`). Implement atomic, rebuildable metadata;
restore it on open; persist model/CWD mutations; define override behavior; and
extend `/status` accordingly.

### #21 — complete `/session` lifecycle and legacy import

Issue: https://github.com/zo-ll/oi.c/issues/21

Automatic sessions use private per-session directories, while explicit named
sessions still use flat `.oilog` paths (`src/cli.c:558-572`). The selector,
switch/full replay, rename, trash, restore, permanent deletion, import
confirmation, and recovery flows from `docs/REPL_PLAN.md:43-44` and
`docs/REPL_PLAN.md:90-93` remain unimplemented.

### #22 — sanitize output and render incremental Markdown

Issue: https://github.com/zo-ll/oi.c/issues/22

Assistant bytes are written directly to the terminal
(`src/cli_present.c:129-137`). A model can therefore emit terminal control
bytes, and Markdown is not incrementally rendered. Add a chunk-safe sanitizer
and renderer with malformed UTF-8, split-sequence, and styling-reset tests
before building richer live presentation.

### #23 — resize and concurrent prompt redraw

Issue: https://github.com/zo-ll/oi.c/issues/23

The current prompt can draw and redraw edited text, but it does not handle
`SIGWINCH` or compose prompt redraw with asynchronous model/tool output.
Implement terminal-width changes, multiline reflow, and a single redraw
coordinator while preserving the separation at
`docs/REPL_PLAN.md:78-80`.

### #24 — cancellation, signals, and recoverable errors

Issue: https://github.com/zo-ll/oi.c/issues/24

The controller blocks on the active conversation
(`src/cli_repl.c:154-166`) and exits after a turn error
(`src/cli_repl.c:167-171`). `Ctrl+C` currently clears prompt input but cannot
cancel an active request/tool. Add signal-safe notification, active-turn
cancellation, repair persistence, graceful `/exit`, and return-to-prompt
classification for recoverable failures.

### #25 — one-slot queued input and safe-boundary steering

Issue: https://github.com/zo-ll/oi.c/issues/25

Queue record/replay shapes exist, but active input is not read while a turn is
running. Add one pending slot, durable enqueue/resolution audit records, safe
tool-boundary steering, startup recovery, and immediate execution after the
current tool completes. New tool calls must not begin ahead of queued input.

### #26 — permission selector and live tool rendering

Issue: https://github.com/zo-ll/oi.c/issues/26

`/permissions` can mutate policy at an idle prompt
(`src/cli_command_dispatch.c:70-97`), but per-tool approval still uses the old
direct controlling-terminal path and does not participate in REPL redraw.
Tool output events are ignored by presentation
(`src/cli_present.c:148-151`). Implement REPL-owned approval UI, confirmation
before elevating to `allow`, bounded live output, statuses, cancellation, and
safe redraw.

### #27 — `/compact` and durable source-range checkpoints

Issue: https://github.com/zo-ll/oi.c/issues/27

Checkpoint records and replay support already exist, including exact source
ranges (`test/test_cli_history_codec.c:120-147`), but no runtime compaction
flow emits them. Implement `/compact [N]`, retain eight completed turns by
default, make the append failure-atomic, rebuild active context, and recover
cleanly after interruption. Do not add vector retrieval to this milestone.

### #28 — complete `/status`

Issue: https://github.com/zo-ll/oi.c/issues/28

Current `/status` prints session ID, model, permissions, and process CWD
(`src/cli_command_dispatch.c:43-60`). It still needs endpoint, timeout,
effective session CWD, queue state, checkpoint state, failure state, and any
other agreed non-secret runtime information.

### #29 — user and developer documentation

Issue: https://github.com/zo-ll/oi.c/issues/29

The README still documents one-shot CLI use and old flat session behavior
(`README.md:54-80`). It does not explain REPL startup, keys, slash commands,
automatic state paths, metadata, switching/import, compaction, queued input,
or installation specifically for interactive use.

### #30 — verification matrix and release gate

Issue: https://github.com/zo-ll/oi.c/issues/30

Add the missing Markdown/sanitization, resize/redraw, signals, steering,
queued recovery, session lifecycle, and compaction tests required by
`docs/REPL_PLAN.md:132-143`. Fix the current macOS `<pty.h>` build failure,
then require the complete CI matrix to pass before declaring the REPL
milestone complete.

## Recommended implementation order

Continue using small commits with one concern and its tests:

1. Fix the macOS PTY portability regression from #30 so every subsequent
   commit has a meaningful native-platform signal.
2. Implement the sanitizer and incremental renderer from #22. All later
   asynchronous model/tool presentation should depend on this safe output
   boundary.
3. Add atomic metadata plus durable `/model` and `/cwd` from #20.
4. Build the resize/redraw coordinator from #23.
5. Add active-turn signals, cancellation, and recoverable error handling from
   #24.
6. Add the one-slot queue and safe-boundary steering from #25.
7. Move permission prompts and tool progress into the coordinated UI for #26.
8. Implement checkpoint generation and `/compact` for #27.
9. Complete session selection/lifecycle and legacy import for #21 once the
   metadata and controller primitives are stable.
10. Complete `/status` (#28), documentation (#29), and the full release gate
    (#30).

Keep domain ownership strict:

- record serialization/replay belongs in `cli_history*`;
- files, metadata, naming, and lifecycle belong in `cli_sessions`;
- model/tool sequencing and safe boundaries belong in `cli_conversation`;
- controller state, signals, queue policy, and command coordination belong in
  `cli_repl`;
- byte sanitization, Markdown state, and redraw belong in `cli_render`;
- editing and selection state belong in the editor/prompt-state stack;
- tool definitions and policy decisions remain in `cli_tools`.

Do not bypass these boundaries by letting command dispatch directly manipulate
session files, letting conversation callbacks emit ANSI, or letting terminal
code append history records.

## Developer setup

Install a C11 compiler, GNU Make, and OpenSSL development headers, then:

```sh
make
make check
```

Build artifacts are under `build/`. The CLI is `build/oi`
(`README.md:13-32`). Useful additional checks are:

```sh
make CC=clang check
make abi-check
make asan
make ubsan
make tsan
make valgrind
make fuzz-run
```

The sanitizer targets rebuild into isolated directories
(`Makefile:213-232`). On some Linux hosts TSan needs reduced ASLR entropy; the
reason and commands are documented at `Makefile:222-230`.

CLI-private tests cannot use the ordinary public-library test pattern when
they depend on private source files. Add the exact required `src/cli_*.c`
dependencies to a dedicated rule, following `Makefile:118-167`. PTY tests also
need the platform-specific PTY header/library treatment used by
`test/test_cli.c` and `test/test_cli_prompt.c`; this is currently incomplete on
macOS.

Installation builds and installs only the program, public library, shared
library links, and public headers; it does not install the test suite
(`Makefile:74-83`):

```sh
make
sudo make install
```

For a user-local installation:

```sh
make
make PREFIX="$HOME/.local" install
```

Ensure `$HOME/.local/bin` is on `PATH`. Set `OI_API_KEY` before a real model
request. Bare `oi` on a terminal enters the current REPL; `oi "prompt"` remains
one-shot.

## Handoff checklist

Before beginning new work:

- read `docs/REPL_PLAN.md` and the three ADRs;
- inspect the relevant open issue and its acceptance criteria;
- confirm `git status --short --branch` is clean;
- run the narrow tests for the module being changed;
- run `make check` before every focused commit; and
- push and confirm the associated GitHub Actions jobs.

Before calling the REPL milestone complete:

- all issues #20 through #30 are closed by implemented and documented
  acceptance criteria;
- ordinary, integration, PTY, sanitizer, Valgrind, fuzz, ABI, GCC, Clang, and
  native macOS CI are green;
- one-shot stdout behavior remains backward compatible;
- no terminal control bytes can reach the user unsanitized;
- interrupted turns, queued input, session switching, and compaction recover
  from durable history; and
- README installation and usage instructions match the shipped behavior.
